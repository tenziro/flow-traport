# 내 업무 화면(`/tasks`) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로그인한 사람이 담당인 업무를 프로젝트별 아코디언으로 전량(실측 880건) 보여 주는 `/tasks` 화면을 만든다.

**Architecture:** flow REST `/user/projects`로 프로젝트를 받고, 프로젝트마다 `tasks/filter`에 담당자 필터(`WORKER_ID IN <세션 userId>`)를 걸어 서버측에서 내 업무만 받는다. 동시 10 · 프로젝트당 최대 3페이지 · 응답은 60초 fetch 캐시. 프로젝트별로 안 끝난 것/완료를 갈라 아코디언 카드 하나로 만들고, 업무 한 줄은 기존 `TaskItem`을 그대로 쓴다.

**Tech Stack:** Next.js 16 App Router(서버 컴포넌트), TypeScript, Tailwind v4, `node:test`(tsx).

## Global Constraints

- 담당자 필터 값은 **반드시 `getSession()`의 `userId`**다. 요청 파라미터로 받지 않는다 — 공용 API 키에 남의 ID를 넣으면 그 사람 업무가 그대로 나온다 (PRD §8.1).
- API Key는 로그·메시지·커밋에 남기지 않는다.
- 완료 판정은 `optionCategory === "2"`. `STTS`(base)와 `STATUS`(커스텀) 두 체계가 공통으로 주는 값이 이것뿐이다 (PRD §6.5).
- 상태 라벨: `optionName`이 있으면 그것, 없으면 `STTS` 코드표(`0` 대기 / `1` 진행 / `2` 완료 / `3` 보류 / `4` 피드백).
- REST 분당 120회 상한. 이 화면 한 번이 ~60회다 → 60초 캐시 필수.
- 완료 업무 줄은 **읽기만** 한다 (`TaskActions` 없음).
- 한국어 주석·문구. 문구는 `docs/TEXT_GUIDE.md`를 따른다.
- 버전: 신규 기능 → `1.1.0` → `1.2.0`.
